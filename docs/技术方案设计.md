### 1.2 SQLAlchemy 模型关键代码示例

#### Article 模型

```python
from sqlalchemy import Column, Integer, String, Text, Enum, Boolean, DateTime, JSON
from sqlalchemy.orm import relationship
from datetime import datetime, timezone

class Article(Base):
    __tablename__ = "articles"

    id = Column(Integer, primary_key=True)
    title = Column(String(200), nullable=False)
    content = Column(Text, default="")
    images = Column(JSON, default=list)
    status = Column(Enum("draft", "published", name="article_status"), default="draft")
    extra_fields = Column(JSON, default=dict)
    author_id = Column(Integer, ForeignKey("users.id"), nullable=True)
    created_at = Column(DateTime, default=lambda: datetime.now(timezone.utc))
    updated_at = Column(DateTime, default=lambda: datetime.now(timezone.utc), onupdate=lambda: datetime.now(timezone.utc))
    is_deleted = Column(Boolean, default=False)

    live_codes = relationship("LiveCode", back_populates="article")
```

#### LiveCode 模型

```python
class LiveCode(Base):
    __tablename__ = "live_codes"

    id = Column(Integer, primary_key=True)
    code = Column(String(16), unique=True, nullable=False, index=True)
    article_id = Column(Integer, ForeignKey("articles.id"), nullable=False, index=True)
    is_active = Column(Boolean, default=True)
    qr_config = Column(JSON, default=dict)  # {size, logo_path, caption}
    scan_count = Column(Integer, default=0)
    extra_data = Column(JSON, default=dict)
    created_at = Column(DateTime, default=lambda: datetime.now(timezone.utc))
    is_deleted = Column(Boolean, default=False)

    article = relationship("Article", back_populates="live_codes")
    scan_logs = relationship("ScanLog", back_populates="live_code")
```

#### ScanLog 模型

```python
class ScanLog(Base):
    __tablename__ = "scan_logs"

    id = Column(BigInteger, primary_key=True)
    live_code_id = Column(Integer, ForeignKey("live_codes.id"), nullable=False, index=True)
    scanned_at = Column(DateTime, default=lambda: datetime.now(timezone.utc), index=True)
    ip_address = Column(String(45), nullable=True)
    user_agent = Column(String(500), nullable=True)
    referer = Column(String(500), nullable=True)
    extra_data = Column(JSON, default=dict)

    live_code = relationship("LiveCode", back_populates="scan_logs")
```

### 4.2 扫码跳转逻辑（跳转路由）

```python
@router.get("/l/{code}")
async def redirect_live_code(code: str, request: Request):
    # 1. 查询活码
    live_code = await live_code_service.get_by_code(code)
    if not live_code or not live_code.is_active:
        raise HTTPException(status_code=404, detail="活码不存在或已停用")

    # 2. 查询文章
    article = await article_service.get(live_code.article_id)

    # 3. 异步记录扫码日志（不阻塞跳转）
    background_tasks.add_task(
        stats_service.record_scan,
        live_code_id=live_code.id,
        ip=request.client.host,
        user_agent=request.headers.get("user-agent"),
        referer=request.headers.get("referer"),
    )

    # 4. 更新活码扫码计数缓存
    await live_code_service.increment_scan_count(live_code.id)

    # 5. 返回文章展示页
    return templates.TemplateResponse("article/view.html", {
        "request": request,
        "article": article,
        "live_code": live_code,
    })
```

## 6. 工程原则在技术方案中的应用

### 6.1 分层架构与关注点分离

```
┌─────────────────────────────────────────────────────────┐
│  Router Layer    (app/api/)     HTTP 请求/响应编解码       │
│  ─────────────────────────────────────────────────────── │
│  Service Layer   (app/services/) 业务逻辑、编排、校验      │
│  ─────────────────────────────────────────────────────── │
│  Repository Layer (app/models/)  数据库 CRUD 操作抽象     │
│  ─────────────────────────────────────────────────────── │
│  Model Layer     (app/models/)   数据结构和关系定义        │
└─────────────────────────────────────────────────────────┘
```

**规则：**
- 路由层不直接调用 ORM，必须通过 Service 层
- Service 层不直接操作 HTTP 对象（Request/Response），接收纯数据参数
- Service 层方法签名使用 Pydantic 模型，不使用 ORM 模型作为参数
- 数据访问层不包含业务逻辑，只做查询和持久化

### 6.2 依赖倒置（DIP）实践

```python
# 正确的依赖方向：高层模块依赖抽象
# app/api/articles.py
from app.services.article_service import ArticleService

# app/services/article_service.py
from app.models.article import Article  # 依赖低层 ORM 模型

# 数据访问抽象：通过 Repository 模式
class ArticleRepository:
    async def get_by_id(self, id: int) -> Article | None: ...
    async def create(self, data: dict) -> Article: ...

class ArticleService:
    def __init__(self, repo: ArticleRepository):
        self.repo = repo  # 依赖注入，而非直接 new
```

### 6.3 开闭原则（OCP）实践

**扩展字段机制：** 新增内容类型不修改 Article 模型
```python
# 新增地图插件时，Article 模型不变
extra_fields = {
    "map": {"lat": 23.1, "lng": 113.3},
    # 未来新增的插件类型继续加 key
}
```

**Resolver 模式：** 新增活码目标类型不修改路由逻辑
```python
class TargetResolver:
    _handlers: dict[str, TargetHandler] = {}

    @classmethod
    def register(cls, type_: str, handler: TargetHandler):
        cls._handlers[type_] = handler

    # 新增类型只需调用 register()，无需改路由代码
```

### 6.4 单一职责（SRP）实践

```
每个 Service 文件职责：
  article_service.py   → 仅文章 CRUD + 发布状态管理
  live_code_service.py → 仅活码生成 + 状态管理
  qr_service.py        → 仅二维码图片生成 + Logo 处理
  stats_service.py     → 仅统计查询 + 导出
  upload_service.py    → 仅文件上传 + 格式校验
```

**行数警戒线：** 单个文件 > 300 行或单个函数 > 50 行时，必须拆解

### 6.5 DRY 实践

- 数据库查询逻辑封装在 Repository 层，不在 API 路由中重复写查询
- 分页、排序、软删除过滤等通用逻辑抽取为 Mixin 或 Base Repository
- 配置常量集中管理在 `app/config.py`，各模块通过 `from app.config import settings` 引用
- 错误响应格式统一，不散落在各模块

### 6.6 KISS 实践

- 第一版不做缓存层（Redis），SQLite 查询性能足够单用户
- 图片处理直接用 Pillow，不上 ImageMagick 或其他第三方服务
- 批量生成用 Python 标准库 zipfile，不上第三方压缩库
- 富文本编辑器用 Quill 轻量方案，不上复杂编辑器框架

### 6.7 YAGNI 决策清单

| 不做 | 理由 | 替代方案 |
|------|------|---------|
| 多用户/权限 | 第一版单用户，不确定是否需要 | 预留 User 表 |
| 文章版本管理 | 用户未提，且改造无成本 | 不做 |
| Redis 缓存 | 单用户场景不需要 | 直接查数据库 |
| 消息队列 | 扫码量不大，后台任务足够 | FastAPI BackgroundTasks |
| 全文搜索 | 当前文章量少，LIKE 查询足够 | 后续加 Elasticsearch |

### 6.8 防御式编程实践

- 所有用户输入（标题、配置参数、图片文件）经过 Pydantic 模型校验
- 文件系统操作（图片上传、ZIP 打包）包裹 try-except，失败时返回明确错误
- 数据库操作使用事务上下文管理器，确保部分失败时回滚
- 扫码跳转路径使用 BackgroundTasks 异步记录日志，不阻塞主流程
- 二维码生成参数校验边界值（尺寸范围、Logo 大小比例）

### 6.9 最小惊讶原则实践

- RESTful 接口命名：`/api/v1/articles` 而非 `/api/v1/getArticles`
- 错误响应格式统一：`{"detail": "错误描述", "code": "ARTICLE_NOT_FOUND"}`
- 分页接口统一参数：`?page=1&page_size=20`，响应格式统一
- 时间格式统一：ISO 8601 —— `2026-08-17T15:30:00Z`
- HTTP 状态码语义准确：200 成功、201 创建、400 参数错误、404 未找到、500 服务器错误
